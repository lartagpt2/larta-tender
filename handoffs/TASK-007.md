Дополнительные детали поведения:

- При первом коммерческом этапе фиксируется последняя полная подтверждённая версия без этапа каждого существующего участника. Черновики базой не становятся.
- Поздний участник получает базовую цену только явным действием закупщика с выбором собственной подтверждённой версии. Цена действует с текущего этапа, не заполняет прошлые этапы задним числом.
- Ответ received требует полной сопоставимой версии того же предложения/этапа; чужая, первоначальная, не относящаяся к этапу или непроверенная версия отвергается. Фиксация окончательна; исправление — новый этап с объяснением.
- Нет ответа и ещё не зафиксированный ответ различаются. Для ожидания процент неизвестен; no_reply при известной цене даёт 0%. Отозванное предложение не восстанавливается последующим no_reply.
- В пределах тендера общий SHA означает только общий оригинал. Цены, ответы, базовые ссылки, контакты и отчёты привязаны к отдельным поставщикам/предложениям.
- История черновиков сохраняет старые тему/текст/адресатов. Старую замещённую редакцию нельзя незаметно перезаписать; источники получателей и связь редакций сохраняются в audit.

## 5. Расхождения с заданием, риски и долги

- Автоматическая почтовая отправка не реализована и не включена: только draft, без send endpoint/SMTP/очереди.
- ZIP остаётся отдельным открытым вопросом ИТ/ИБ. Общий загрузчик продолжает явно отклонять архивы.
- Источник аккредитации — ручная загрузка файла из отдельного ресурса с обязательным названием источника; внешняя интеграция/скачивание отчётов без утверждённого API не добавлялись.
- `document.purpose` не расширен: используется описанный совместимый адаптер роли. Если владельцу нужна отдельная purpose/таблица хранения, потребуется отдельная версия миграции и разрешение на её применение.
- Зафиксированные ответы/базовые цены не редактируются: исправление коммерческих данных — следующий этап. Это сохраняет воспроизводимую историю.

- Журнал на экране ограничен последними 500 событиями, строки в БД сохраняются. Истории отчётов/черновиков пока без пагинации. Большие тендеры и нагрузка не испытывались.

- Унаследованный dev-профиль содержит некорректное отображаемое имя; UUID и время подтверждения отображаются, профиль не заменялся выдуманным именем. Авторизация остаётся локальным dev-механизмом; корпоративный production auth/ИБ-шлюз/техническая изоляция — прежние отдельные вопросы.
