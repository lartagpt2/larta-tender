## 5. Ограничения и оставшиеся вопросы

- Остался один реальный пропуск модели на этом синтетическом наборе: header currency ru-missing=null вместо RUB. Догадка по умолчанию не добавлялась. Его исправление потребовало бы отдельного явно обозначенного извлечения/подтверждения валюты, а не изменения gold.
- 99,75% относится только к этим 10 знакомым синтетическим документам после адресных исправлений. Это не независимый holdout для новой версии и не гарантия промышленной точности. Многократная статистика/новый слепой корпус не выполнялись.
- Формат ИНН защищён от числовой нормализации и обнаруживает неверную длину, но не гарантирует правильность всех цифр OCR. Контрольная сумма не применяется к фиктивным номерам; правила иностранных регистрационных номеров требуют отдельного согласования. Сомнительные данные остаются черновиком.
- Evidence-восстановление намеренно ограничено уникальным описанием и соседними размеченными строками. Для сложных/неоднозначных таблиц данные могут остаться null, а не приниматься из чужой строки. Для vision-фрагментов по-прежнему требуется сверка человеком с оригиналом.
- FIFO реализован для поддерживаемого режима одного экземпляра API с файловым store; распределённая очередь, multi-host ordering, приоритеты, длительная нагрузка, мониторинг/retention/backup остаются отдельными задачами. При равных legacy timestamps используется ID как стабильный порядок.
- При неизвестной валюте сохраняются буквальные значения и предупреждения; это не делает КП сопоставимым и не выполняет конвертацию. Разные валюты не суммируются.
- Условия ИТ/ИБ по ZIP, ОС-изоляции, AV, серверной нагрузке остаются открытыми. Реальные документы до отдельного разрешения запрещены.
