# TASK-006: ручная проверка и сравнение КП

Экран проверки: `/review?tenderId=<UUID>`. Сравнение: `/comparison?tenderId=<UUID>`.
Из карточки тендера доступны ссылки «Проверить КП» и «Сравнить предложения». В меню S04/S05 можно выбрать тендер.

## Контекст и сохранение

Оригинал document/blob общий и неизменяемый. Коммерческое предложение определяется `(tender_id, supplier_id, lot_id)`; его offer_package создаётся отдельно от загрузочного пакета оригинала. Каждая версия ссылается на source_document_id, а подтверждение `offer.verification.v1` также содержит receiptId, supplierId, lotId, offerId и versionId.

Запрос, UI и журнал явно фиксируют поставщика и поступление. Данные читаются по offer/version, не по одному SHA/document_id. Общий PDF у A и B не копирует цену, срок, расходы, исходные значения или источники A в B. Статус общего document не становится confirmed после подтверждения одного поставщика.

При первом сохранении создаются version 1 (`is_initial=true`, ручной перенос оригинальных значений) и version 2 (текущие проверяемые данные). Все последующие сохранения добавляют версию. Оригинальная транскрипция блокируется после первого сохранения. Изменять байты/имя/MIME/SHA нельзя; старые версии и решения защищены существующими триггерами 002.

Каждый изменённый скаляр/массив получает sourceType/sourceNote + серверного автора/дату; неизменённые значения сохраняют прежний источник. Структурное сравнение не зависит от порядка ключей JSONB. Исправление срока по телефону не превращает остальные поля в телефонные.

Замечания по отсутствующим полям, валюте, НДС, составу и расходам вычисляет сервер. Их нельзя снять поддельным ID. Дополнительные ручные вопросы получают отдельные UUID; существующий вопрос снимается только явным resolveQuestionIds, с основанием в новой версии. Исправление срока не снимает другой вопрос автоматически.

## API

| Метод | Маршрут                             | Назначение                                                                                |
| ----- | ----------------------------------- | ----------------------------------------------------------------------------------------- |
| GET   | `/api/tenders/:id/verification`     | Тендер, лоты/позиции, поставщики, оригиналы/поступления и отдельные версии предложений    |
| POST  | `/api/tenders/:id/verification/lot` | Явное создание первого лота без позиций; body `{expectedRevision}`; повтор/конфликт — 409 |
| POST  | `/api/tenders/:id/verification`     | Ручная версия по выбранному контексту, проверка и audit                                   |
| GET   | `/api/tenders/:id/comparison`       | Серверная транспонированная модель; optional lotId, mode=lot/items, itemId                |
| GET   | `/api/tenders/:id/comparison.csv`   | Те же строки/столбцы и атрибуция, те же query-параметры                                   |

Body проверки: supplierId, lotId, documentId, receiptId, expectedVersion, contextConfirmed=true, intent=draft/confirm, fields, original (только при первом сохранении), items, costs, costsEnabled, sourceType, sourceNote, newQuestions[], resolveQuestionIds[].

fields/original: amount:string|null, currency:RUB/USD/EUR/CNY|null, vatMode:included/excluded/unknown, paymentTerms:string|null, deliveryTerms:string|null, compliance:matches/partial/unknown.

items: lotItemId, quantity (положительная строка NUMERIC), unit, unitPrice:string|null. costs: name, amount:string|null, currency|null, treatment=included/add/unknown. До 100 позиций и 20 расходов; новые вопросы до 20 за сохранение, всего до 100.

Для confirm обязательны валюта, оплата, срок и цена для лота без позиций. При наличии состава цена рассчитывается по позициям; недостающие цены/состав/соответствие/НДС/расходы и открытые вопросы оставляют needs_review. draft позволяет явно сохранить неизвестные поля. Непустой sourceNote и подтверждение контекста обязательны для обоих вариантов.

UUID, enum, денежные/количественные строки, принадлежность лота/позиций/поставщика/оригинала/поступления проверяет сервер. Последняя версия сверяется под блокировкой тендера: устаревший expectedVersion — 409. Наблюдатель: чтение разрешено, запись 403; посторонний: 404. Production access по-прежнему выключен прежним DataContext.

## Формулы и границы

- Decimal.js **10.6.0**, MIT, закреплён как production dependency. Ранее пакет уже присутствовал транзитивно в dev. Decimal.clone с precision=60 и ROUND_HALF_UP, без глобальной конфигурации и без Number/parseFloat для сумм.
- Входные суммы до 14 целых + 6 десятичных знаков, количества до 12 + 6; произведение может иметь до 12 десятичных знаков и выдаётся без принудительного округления до копеек. Проценты округляются до 4 знаков.
- UI принимает десятичную запятую и пробелы; API принимает нормализованную строку с точкой. Пустое поле — null, явно введённый ноль остаётся нулём.
- Если у лота есть позиции: база = сумма всех обязательных `quantity × unitPrice`. Нет цены обязательной позиции — база лота null, рейтинг недоступен. Для лота без позиций используется явно подтверждённая общая цена.
- Количество должно совпасть с составом; единицы нормализуются только по регистру/окружающим пробелам/конечной точке. Конверсий кг↔т и других коэффициентов нет: несовпадение блокирует рейтинг.
- Расходы вручную выключены по умолчанию. Включённый add прибавляется один раз, included не прибавляется. unknown не считается нулём, в том числе при выключенной галочке, если неизвестный расход сохранён в версии.
- Добавляемые расходы лота не распределяются по позициям без утверждённой методики: режим позиций показывает отсутствие сопоставимой стоимости при таких расходах. Частичный обязательный состав не ранжируется даже по отдельной позиции — консервативное ограничение текущего MVP.
- Для разных валют/НДС-баз общего рейтинга нет; курсы/автоматическое пересчитывание НДС не реализованы. Сортировка мест не объявляет победителя. Равные суммы имеют равное место.
- Скидка `(previous-current)/previous*100`; рост цены сохраняет отрицательный процент, нулевой/неизвестный знаменатель — null. Берутся только сопоставимые проверенные версии. Есть также общее снижение относительно исходной транскрипции при совпадающей базе. Для будущего no_reply чистая функция сохраняет последнюю подтверждённую сумму и 0% изменения; workflow этапов/ответов здесь не вводится.
- История цен относится к лоту. В режиме позиций актуальная база относится к выбранной позиции; остальные позиции также показаны отдельными строками.
- Аккредитация: без отчёта — красный «Нет проверки». Чтение уже существующего accreditation_report строго по tender/supplier; даже общий оригинал отчёта не переносит статус на другого поставщика. Загрузка отчётов не добавлялась.

## Экспорт

UTF-8 BOM, CSV с `;`, CRLF, кавычками и экранированием кавычек. Экспорт строится из того же comparison model, включает цены, вопросы, источники/комментарии, акторов/даты, IDs контекста и SHA. Чистые отрицательные числа экспортируются без изменения. Потенциально формульный текст получает защитный апостроф.

## Хранение и ограничения

Новых миграций/DDL нет; используются существующие offer, offer_package, offer_version, offer_item, cost_component, field_decision и audit_event. Метаданные подтверждения версионированы ключом offer.verification.v1; JSON содержит ссылки, проверяемые приложением, а FK основных сущностей остаются в прежних таблицах. Неизвестные старые offer без этого контракта автоматически не переписываются — редактирование возвращает 409 до отдельного разбора.

Данные сравнения вычисляются при чтении, не являются закреплённым calculation_run/решением комиссии. При параллельных изменениях пользователь обновляет модель; для последующего официального снимка/подписи потребуется отдельный контракт. Пагинация историй и нагрузочные испытания не входят в текущую локальную приёмку.

ZIP остаётся отдельным вопросом ИТ/ИБ и не препятствует TASK-006. OCR/LLM, отправка почты, новые этапы/переторжка и функции TASK-007 не добавлялись.
