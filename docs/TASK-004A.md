# TASK-004A: извлечение текстового PDF-ТЗ

## Diagnosis и границы

На исходной версии TASK-004 (89a18a6) uploadSpecification сохранял файл через FileStore и PgScopeRepository.attach; документ получал status=uploaded. Worker/парсер не вызывались, черновика не было. Это была предусмотренная ветка отсутствующего обработчика, а не доказанный дефект конкретного PDF. Существующий загрузчик и его защита оригинала сохранены.

Добавлены отдельные извлечение текста, структурный парсер и операция подтверждения. Это локальная обработка текстового слоя PDF; OCR, Ollama и внешние модели не вызываются. Исходный пользовательский ТЗ.pdf не приложен к постановке и не проверялся/не коммитился. Проверки используют синтетический трёхстраничный PDF с семью заданными артикулами и количествами, без контактных данных.

## Библиотека и ограничения

Выбран и закреплён pdfjs-dist 6.5.438, лицензия Apache-2.0. До этого PDF-библиотек в проекте не было. Node engine пакета совместим с используемым Node 24. Выбор позволяет обойтись без глобальной установки Poppler, Python-пакетов или службы. Согласование ИТ/ИБ для промышленного применения остаётся обязательным; его наличие агент не заявляет.

Первичные источники: [PDF.js API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html), [лицензия Mozilla](https://github.com/mozilla/pdf.js/blob/master/LICENSE), [пакет](https://www.npmjs.com/package/pdfjs-dist).

Обработка выполняется в отдельном Node Worker: максимум 20 МиБ PDF, 30 страниц, 100 000 символов на страницу и 500 000 суммарно, timeout 15 секунд, V8 old generation 256 МиБ, не более 2 активных workers на процесс. Worker завершается после ответа/ошибки/timeout. Ошибки возвращают фиксированные diagnostic codes; текст и исключения PDF в логи не выводятся. Input — только байты, без URL; fetch отключён, isEvalSupported=false, без rendering, системных шрифтов и WASM. Скрипт scripts/pdf-text-worker.mjs и зависимость должны поставляться вместе с API при развёртывании из монорепозитория.

В worker передаются только SystemRoot и TEMP/TMP рабочей области, без переменных БД и API-токена.

Worker — ограничение исполнения, не полноценная ОС-песочница. V8-лимит не является жёстким лимитом всего RSS. До корпоративных файлов необходимы антивирус/ИБ-приёмка и согласованная изоляция. Формальные ограничения по страницам/символам реализованы; тест timeout выполнен, исчерпывающие нагрузочные/атакующие PDF тесты не заявляются.

## Поток данных

1. Оригинал и SHA256 сохраняются прежним загрузчиком, без изменения байтов.
2. При открытии загруженного PDF интерфейс получает существующий черновик или вызывает отдельный POST извлечения. TXT сохраняет прежнее поведение ожидания, без PDF-парсера.
3. PdfTextExtractionService возвращает страницы, hasText, diagnostics. Слова собираются в строки по координатам PDF, с сохранением страницы-источника.
4. Парсер поддерживает нумерацию 1./6., переносы, тире, количество + шт./шт. Полное имя и начальные цифры артикула сохраняются. Версии/реквизиты/подписи и технические строки исключаются из позиций. Пропуски количества/единицы — null, не ноль. Неподдерживаемый перечень требует ручной проверки.
5. Технические группы сопоставляются по явным диапазонам позиций либо по предшествующему блоку списка. Для нестандартной структуры автоматическое сопоставление не гарантируется: закупщик обязан сверить источник.
6. До подтверждения в lot_item ничего не записывается. Черновик редактируется, технические условия показаны отдельно. Кнопка источника открывает исходный PDF на странице и извлечённый текст страницы.
7. Подтверждение проверяет owner/buyer/manager, UUID, поля, положительные NUMERIC-строки, sourceIndex, revision и отсутствие уже подтверждённого/заполненного состава. В одной транзакции сохраняются LotItem с tech_requirements, FieldDecision и AuditEvent. Режим по позициям становится доступен, исходный PDF не меняется.
8. Одинаковое повторное подтверждение возвращает сохранённый состав; другой payload для подтверждённого run — 409. Повторная загрузка/извлечение этого оригинала не создаёт LotItem и не затирает правки. Подтверждённый run имеет приоритет перед более поздним незавершённым/черновым извлечением.

## Хранение без миграции

Используются уже применённые таблицы 002:

- extraction_run: версия PDF.js, parser_version=tz-list-v1, prompt_version=none, состояние/время;
- blob + FileStore: отдельный JSON-артефакт со страницами, документом, runId, sourceSha и версиями; оригинальный blob не заменяется;
- extracted_field: versioned tz.result.v1 и tz.item.<sourceIndex>, nullable confidence, отдельный run_id;
- evidence_reference: страница, исходный фрагмент, SHA исходного PDF;
- field_decision: append-only tz.scope.confirmed.v1 с runId, исходной SHA, автором и принятыми исправлениями;
- lot_item.tech_requirements: подтверждённые технические условия соответствующей позиции.

Ссылка на SHA производного артефакта находится в versioned JSON результата, а не в новой колонке/FK. Это локальное решение на имеющейся модели; при расширении контрактов извлечения следует отдельно рассмотреть выделенную таблицу артефактов. Данные только в согласованной larta_test_task003. Ни 001/002, ни существующая postgres не изменялись.

## API

| Метод | Маршрут                                                    | Назначение                                                                       |
| ----- | ---------------------------------------------------------- | -------------------------------------------------------------------------------- |
| GET   | /api/tenders/:id/tz/:documentId/draft                      | Последний/подтверждённый результат либо null                                     |
| POST  | /api/tenders/:id/tz/:documentId/extractions                | Ограниченное локальное извлечение; draft/needs_review/needs_ocr/failed/confirmed |
| GET   | /api/tenders/:id/tz/:documentId/source/:page               | Производный текст страницы с проверкой доступа                                   |
| POST  | /api/tenders/:id/tz/:documentId/extractions/:runId/confirm | revision + исправленные позиции с sourceIndex; создание окончательного состава   |

needs_ocr относится к результату извлечения; документ при этом хранится как needs_review, а не как подтверждённый. Пустой текст не является успешным распознаванием состава. Нерабочие/защищённые PDF возвращают безопасный failed с diagnostic code.

Реестр КП, поставщики, аккредитация, офферы и исторические цены не изменялись. TASK-005 не начат.
