## Рабочие правила и защита

- Архивировать/восстановить может владелец либо buyer/manager своего тендера.
  Reviewer читает. Корзина дополнительно требует `trash_synthetic` и актуальную
  подтверждённую синтетику. Подтверждение происхождения требует `classify_synthetic`.
- После изменения рабочих данных, receipts, versions или OCR/reviews синтетику
  нужно подтвердить повторно. Фиксируются content revision и SHA списка OCR.
- `working` нельзя перевести в synthetic через API. Рабочий тендер можно архивировать.
- Исследовательские Gate D/E/F/G, текущий demo и legacy fixture защищены от всех
  lifecycle/classification операций точным списком ID в SQL и API. Список не обходится
  отдельным правом. Снятие исключения потребует отдельного проверенного изменения.
- Активные jobs блокируют archive/trash/classification. Lock родительского tender
  сериализует операции и все изменения прямых/косвенных зависимостей. Изменившийся
  preview, включая аудит и OCR, возвращает 409; требуется новый просмотр.
- Архив/корзина доступны через прямые ссылки для чтения. Записи/файлы не удаляются.
  Общие blob и JSON `artifactSha`, suppliers и app_user не собираются и не очищаются.
- После 003 нельзя возвращать старые workers, обходящие файловый fence. Выключение
  UI-флага не является откатом схемы и не возвращает архивы в активное состояние.

## Восстановление и откат

Обычное восстановление — `restore` с новым preview и точным title/ID; архив/корзина
возвращаются в Active с сохранением классификации, всех оригиналов, цен и истории.
Из корзины восстанавливает обычный владелец/buyer/manager; trash capability нужна
для помещения, а не для восстановления. Повторная операция со старым hash отклоняется.

При ошибке до COMMIT migration runner откатывает транзакцию. После успешного
COMMIT автоматического down/DROP нет: они уничтожили бы историю и защиту.
При инциденте остановить writers, оставить схему/данные, подготовить исправляющий
forward PR. Аварийный backup восстанавливать в новый контур и переключать приложение
только по решению владельца/ИТ. Не перезаписывать текущие audit/versions.

Физическое удаление, GC файлов и массовая очистка не реализованы и не разрешены.
