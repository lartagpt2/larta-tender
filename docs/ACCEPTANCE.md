# Сценарии приёмки — тестовые данные

Это **целевые критерии**, не результаты уже проведённых тестов. Для каждого Codex прилагает тест, скриншот при необходимости, SHA коммита, команду и фактический исход.

## Создание тендера

- [ ] Создание только по названию: сохранение и переход к загрузке КП; отсутствие ТЗ не блокирует загрузку.
- [ ] Ручной ввод 3 позиций (например, насос × 2, шкаф × 1, монтаж × 1) с разными единицами; данные сохраняются после перезагрузки.
- [ ] Загрузка ТЗ порождает черновик; распознанные позиции не становятся подтверждёнными автоматически.
- [ ] «Пропустить и свернуть» скрывает форму ТЗ; компактная кнопка возвращает её без потери данных.
- [ ] Переключение «по лоту / по позициям» меняет способ сравнения, не меняя оригинал ТЗ.

## Общая загрузка документов

- [ ] Выбрать 5 тестовых файлов разных поставщиков одной операцией без обязательных полей «поставщик» и «email».
- [ ] Через минуту/после перехода на другую вкладку добавить ещё 2 файла: исходные 5 остаются в реестре.
- [ ] Один поставщик прислал PDF + XLSX + EML: группа раскрывается и показывает все 3 документа, включая этапы.
- [ ] Для EML извлечь адрес From с привязкой к конкретному файлу; не изобретать email для PDF без источника.
- [ ] Неопределённый файл — отдельная группа «Поставщик не определён» и действие «Уточнить»; после привязки он перемещается к выбранной компании.
- [ ] Архив с `../` и слишком большим отношением распаковки отклоняется защитой; остальные документы пакета не теряются.
- [ ] Повторная отправка того же idempotency key не создаёт дубли; совпадающее имя файла без одинакового содержимого — не повод затирать оригинал.

## Проверка и сравнительная таблица

- [ ] У поставщика отсутствует срок: статус «Требует проверки». Закупщик вводит «7 дней», источник «Телефон», сохраняет и подтверждает; если других проблем нет, статус «Проверено».
- [ ] При неразрешённом другом замечании после исправления срока статус остаётся «Требует проверки», причина видна.
- [ ] Стоимость двух позиций считается по количеству и цене; отсутствие цены третьей обязательной позиции не превращается в ноль и не допускает ранжирования полного лота.
- [ ] Доп. расходы выключены по умолчанию; по галочке вводится доставка 10 000 ₽. «Включено в цену» не прибавляется повторно.
- [ ] При отсутствующем отчёте аккредитации — красный «Нет проверки». После прикрепления отчёта «Аккредитован» — статус обновляется только у соответствующего контрагента.
- [ ] Сравнительная таблица транспонирована, экспорт соответствует видимым полям и этапам, расчёты делаются на сервере.

## Этапы, версии и переторжка

- [ ] Первоначальная цена 100 000 ₽ сохранена. После 2-го этапа цена 95 000 ₽ — новая строка в **той же** таблице; скидка `(100000−95000)/100000×100 = 5%`.
- [ ] После 3-го этапа цена 90 000 ₽ — скидка этапа `(95000−90000)/95000×100 ≈ 5,2632%`; общая скидка `10%`. Оригинальные версии не перезаписаны.
- [ ] Поставщик не ответил на переторжку: действует 90 000 ₽, ответ «Нет ответа», изменение этапа 0%.
- [ ] В «Переписке» есть действия «Уточнить КП», «Новый этап», «Переторжка» и адресаты из подтверждённых контактов. Кнопки создания черновика не отправляют email автоматически.
- [ ] Журнал фиксирует кто и когда подтвердил поля, добавил аккредитацию, изменил привязку файла и создал этап.

## Нефункциональная и ИБ-приёмка

- [ ] Тесты для расчётов с Decimal (включая отрицательные скидки и деление на ноль), API-валидации, миграций, загрузки нескольких файлов.
- [ ] Разрешения проверяются **сервером**, не только скрытием кнопок в интерфейсе.
- [ ] В логах/API/коммитах нет реальных токенов, паролей, содержимого КП и персональных данных.
- [ ] Резервное копирование и тест восстановления согласованы DBA перед пилотом на корпоративных данных.
- [ ] ИТ/ИБ подтвердили границы среды и допустимые форматы до реальных КП; решение L2/L3 документировано.
