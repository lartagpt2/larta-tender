# Проектные рабочие инструкции

Локальная редакция 1, этап 1, 02.11.2026.
Это документ для будущей реализации, без установки skills и запуска приложений.
До этапа 2 не создавать каркас и не инициализировать Git.

## Архитектура

Сохранить стек исходного плана: Vue 3/TypeScript/Vite/PrimeVue 4 для web; NestJS 11/Fastify 5 для API.
Общие типы размещать в packages/shared. Не помещать серверные секреты и доступ к хранилищу в клиентский пакет.
Интеграции 1С, файлового хранилища и извлечения документов отделять адаптерами; внешние подключения согласовывать отдельно.
DTO проверять на границе API; расчёты цен выполнять детерминированно.

## Файлы и окружение

Перед командами разработки загружать C:\Users\oalimova\ai_project\tools\enter-workspace.ps1.
Перед записью нормализовать абсолютный путь, проверить принадлежность корню и все существующие компоненты на reparse point.
Отклонять обход пути и выход через ссылки; проверку повторять непосредственно перед операцией. Эти проверки не заменяют ограничение прав процесса.
Зависимости, кэши, результаты и журналы держать внутри корня. Системные PATH, реестр, службы и глобальные пакеты не изменять.
Секреты хранить только в игнорируемом .env, а .env.example заполнять без секретов.

## Проверки

После разрешённого создания приложений использовать Vitest для web, Jest для API, Playwright для пользовательских сценариев.
Проверять поведение: обход путей, валидацию загрузок, повторную загрузку, ручные исправления и воспроизводимость расчётов.
Команды запускать из соответствующего проекта с локальными кэшами; необходимые браузеры также хранить внутри корня.
Не заявлять прохождение тестов и изоляцию без фактических результатов.

## Документы

Не отправлять документы и исходники внешним сервисам.
Для извлечённых полей сохранять ссылку на документ и страницу/лист, где возможно.
Не выдумывать отсутствующие данные; отмечать неопределённость и обеспечивать ручную проверку.
До запуска Graphify исключить семантическую обработку документов внешней моделью и проверить сетевое поведение конкретной версии.

## PostgreSQL

Не подключаться к БД без параметров и отдельного разрешения.
Не создавать кластер, не менять конфигурацию PostgreSQL и не применять миграции.
После согласования держать строки подключения в .env; отчёты, журналы и примеры не должны содержать секреты.
