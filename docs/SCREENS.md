# UX-прототипы экранов — функциональное описание для Vue 3

Источник поведения: демонстрационная версия «Тендерный помощник Б+» (см. README). Это сценарии, не обещание готовых Vue-компонентов.

## S01. Список тендеров

- Поиск/фильтры по статусу, категории, закупщику, сроку.
- Столбцы: номер, наименование, категория, срок, статус, количество КП, незакрытые вопросы.
- CTA «Создать тендер»; переход в карточку; мобильное меню закрывается по кнопке, по клику на фон и свайпу влево.
- Две темы: текущая и Larta; палитру сверять с утверждёнными бренд-токенами, не считать демонстрационные цвета официальными.

## S02. Мастер создания тендера

| Режим           | Поля                                              | Поведение                                                       |
| --------------- | ------------------------------------------------- | --------------------------------------------------------------- |
| Вручную         | Название; строки «позиция / количество / единица» | Добавление/удаление строк; доступно сравнение построчно         |
| Загрузка ТЗ     | Название; файл ТЗ                                 | Загрузка → извлечение → черновик → подтверждение закупщиком     |
| Только название | Название                                          | Тендер создаётся без состава; ТЗ или строки добавляются позднее |

После создания: выбор **по лоту / по позициям** на карточке. Если ТЗ пропущено, кнопка «Пропустить и свернуть» прячет форму и оставляет компактную «Загрузить ТЗ позже»; загрузку КП не блокировать.

## S03. Документы — общая загрузка КП

**Одна большая область** «Загрузить все КП и приложения»; `multiple`, drag-and-drop после проверки UX, вложения/архивы разных поставщиков в одной операции. После первой загрузки остаётся кнопка «Добавить ещё КП».

- Не требовать ручного указания поставщика и email **на входе**.
- Для каждого файла сервер создаёт отдельный `Document`, указывает первоначальный этап или выбранный этап; загрузка повторно не уничтожает старые записи.
- Статус: загружается → проверка файла → ожидает распознавания → извлечено/не удалось → требует проверки → подтверждено. Ошибки отдельного файла не откатывают остальные без явного требования атомарности.
- Группировка в реестре: раскрывающаяся **строка поставщика** с количеством документов; внутри список файлов, этап, контакт, канал, статус, действия. Для нераспознанных — «Поставщик не определён», кнопка «Уточнить».
- Источник совпадения показывать: EML From, подтверждённый контакт, текст документа с доказательством, имя файла (гипотеза, требует подтверждения). Ни один эвристический match не должен приписывать поставщика окончательно без проверки.
- Внутри файлов поставщика отображаются и исходное КП, и приложения, и ответ после переторжки; один файл может быть приложением к КП, а архив — контейнером нескольких файлов.

## S04. Проверка КП

- Слева просмотр исходного документа/страницы; справа структурированные поля с уверенностью **как подсказкой**, значением, исходной цитатой/координатой и статусом.
- Поля: поставщик, контакты, цена, валюта, НДС, условия оплаты, срок, доставка/Incoterms, соответствие ТЗ, прочие критерии категории.
- Закупщик может вручную исправить или дополнить (например, информация по телефону); обязательны источник, комментарий и автор/время изменения; «Сохранить и подтвердить» пересчитывает статус, если нет иных открытых вопросов.
- Массовая проверка не стирает версию извлечения и оригинал.

## S05. Сравнение

- **Транспонированный вид:** строки — показатели; столбцы — контрагенты.
- Переключатель по лоту/по позициям, если в лоте есть позиции.
- Строка аккредитации: «Нет проверки» красным, пока отсутствует загруженный отчёт. Иные статусы — из заключения, не из предположения модели.
- Исходная цена и стоимость неизменны; для каждого этапа отдельные строки «Цена этапа», «Скидка этапа, %», плюс «Общее снижение, %».
- «＋ Добавить доп. затраты» — галочка с ручной формой: вид, сумма, валюта, «включено/добавить», источник; итог только с явно указанными суммами. Пропуски не заменять нулём.
- При несопоставимых валютах/единицах — предупреждение и блокировка автоматического ранжирования до нормализации по согласованной методике.

## S06. Переписка и этапы

- Действия: «Уточнение КП», «Следующий этап (2-й/3-й/...)», «Запрос улучшения условий / переторжка».
- Пользователь выбирает контрагентов, видит найденные адреса, шаблон и редактируемый текст/комментарий (например, уточнение ТЗ).
- В MVP **только черновики и регистрация ответов**; отправка письма — отдельный этап проекта и только с подтверждением закупщика.
- Ответы загружаются в общую «Документы», привязываются к этапу и добавляют строки в том же «Сравнении». Если ответа нет, прежняя цена переносится как действующая с пометкой «Нет ответа», скидка 0%.

## S07. Аккредитация и проект заключения

- В «Документах» отдельный блок отчётов: файл, поставщик, дата, источник, статус «Аккредитован / С замечаниями / На рассмотрении / Не аккредитован / Заключение не получено».
- История всех отчётов; актуальный статус определяется по согласованной дате/версии, не перезаписывать старый.
- Проект заключения: таблица, критерии, выявленные риски, история цен/скидок, ссылки на документы и оставшиеся вопросы. Решение о победителе принимает человек.

## Общее поведение

Адаптивные таблицы, доступное клавиатурное управление, понятные пустые состояния, раздельные признаки «файл загружен», «распознан», «поле проверено», явные даты/авторы; не раскрывать коммерческие данные в логах/URL.
