# TASK-008 — локальные черновики ТЗ и КП

Реализация Gate B/C поверх TASK-007. Все результаты — `needs_review`, не подтверждение. До отдельного допуска доступен только серверный список SHA-256 синтетических оригиналов. Новых зависимостей и миграций нет.

## Конвейер и границы

1. Существующая загрузка сохраняет оригинал, SHA и независимое поступление. Запуск распознавания — отдельное явное действие в интерфейсе.
2. Backend проверяет доступ к тендеру, право записи, назначение документа, receipt/lot/supplier и разрешённый SHA. Этап берётся из поступления, не из тела запроса.
3. В worker с пределом 20 с / JS heap 256 MiB извлекается текст PDF. Успешный штатный разбор перечня ТЗ имеет приоритет. Страницы без текста растеризуются локально в PNG (до 2 MP / 4 MiB), а не отправляются как PDF в vision API. TXT читается строго UTF-8; XLSX — только буквальные ячейки ограниченного ZIP/XML, без формул/внешних связей/DTD. Библиотека canvas уже была в дереве зависимостей pdfjs; пакеты не устанавливались.
4. Прямой `node:http` обращается только к literal IP 127.0.0.1 или согласованному 10.216.10.116, порту 11434, точной модели qwen3-vl:8b-instruct. Redirect/proxy/cloud fallback отсутствуют. Перед документным запросом проверяются `/api/status` (`cloud.disabled=true`), `/api/show` (vision и отсутствие remote alias), `/api/tags` (закреплённый digest). При недоступности проверки запрос документа не выполняется.
5. Компактный wire-контракт разворачивается в `document-draft-v2`; AJV, проверка evidence по странице текстового источника, Decimal с precision 60, арифметика строк/итога и явные предупреждения. Для скана evidence требует ручной проверки. Confidence всегда null. Пропуски не подменяются нулями.
6. Поля хранят rawValue/value/page/evidenceSnippet/sourceDocumentId. Версии prompt/parser/schema, фактическая модель/digest/время, actor/status history и ручные редакции сохраняются отдельно от бизнес-данных.
7. Подсказки поставщика ищутся только среди участников текущего тендера: точный регистрационный номер, иначе точное имя без учёта регистра. Покупатель не используется как поставщик. Неизвестный ИНН/неоднозначность показаны явно. Выбор кандидата, перенос в пустое поле и подтверждение — отдельные действия человека. Email PDF не становится подтверждённым контактом или EML From.

## Хранилище и API

Использован допускаемый заданием постоянный файловый queue вместо изменения БД: `<STORAGE_ROOT>/document-ai`. Atomic temp + fsync + rename, блокировка wx с PID, восстановление pending/running после завершения старого процесса, до трёх попыток. Абсолютные пути и предки проверяются на выход за рабочую область и ссылки. Это не техническая ОС-песочница.

| Метод и маршрут относительно `/api/tenders/:id` | Назначение                                                                                       |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| GET `/document-ai`                              | До 100 последних кратких записей, enabled/syntheticOnly                                          |
| GET `/document-ai/:jobId`                       | Полный результат, источники и история                                                            |
| POST `/document-ai`                             | documentId, kind; для КП receiptId/lotId, supplierId необязателен; retryOf создаёт новую попытку |
| POST `/document-ai/:jobId/review`               | revision, fields, note, необязательный снимок ручной формы с intent=draft                        |

Идентификатор задания учитывает tender/document/SHA/receipt/supplier/lot/stage, модель/digest, версии parser/prompt/schema и retryOf. Общие байты другого поступления не означают общее подтверждение. Повтор того же запроса идемпотентен. Конфликт ревизии/занятая запись — 409, чужой тендер — 404, недостаточные права записи — 403.

Сохранение ИИ-черновика не создаёт OfferVersion и не меняет сравнительную таблицу. Явное «Сохранить и подтвердить» использует прежний контракт ручной проверки TASK-007. Первоначальная цена, ответы этапов и no_reply не обновляются конвейером распознавания. Для ТЗ сначала перенос в редактор, затем отдельное сохранение состава. Не добавлены отправка писем или обработка ZIP входящих КП.

## Настройка и запуск

Перед командами загрузить окружение рабочей области: `. ..\tools\enter-workspace.ps1` из корня репозитория. Секреты — только в игнорируемом локальном конфигурационном файле; пример параметров: [.env.example](../.env.example).

- `DOCUMENT_AI_ENABLED=false` по умолчанию.
- `OLLAMA_BASE_URL=http://10.216.10.116:11434`, точная модель и закреплённый digest — из [отчёта окружения](./OLLAMA-ENV-REPORT.md).
- `DOCUMENT_AI_TIMEOUT_MS=90000` (допустимо 1000–120000).
- `DOCUMENT_AI_SYNTHETIC_SHA256` — перечень явно разрешённых SHA через запятую. Пустой список запрещает всё. Название файла и клиентские флаги не дают допуска.
- `STORAGE_ROOT` — абсолютный каталог внутри рабочей области; оригиналы и задания должны резервироваться вместе.

В текущем dev/test профиле функция включена только для четырёх известных синтетических SHA (native PDF, scan PDF, этап 2, прежний семипозиционный ТЗ). Для настройки не менялись серверные переменные Ollama/службы/драйверы/firewall. Новые модели не загружались.

Запуск: `npm run dev:api` и `npm run dev:web` в отдельных процессах. Только loopback, UI http://127.0.0.1:5173. Для воспроизведения демо при запущенных серверах: `node scripts/seed-task008-demo.mjs --run --extract`; скрипт допускает только существующую тестовую БД larta_test_task003, создаёт новые синтетические записи и не подтверждает цены. Без --extract только подготавливает демо. Без --run не записывает ничего.

## Ограничения и эксплуатационные решения

- Это ограниченная очередь одного API-экземпляра на одном хосте с доверенным файловым доступом, не распределённая СУБД. Инвентарь ограничен 5000 заданиями, ответ списка — 100; пагинация/архивация/retention/резервирование требуют следующего решения. При повторном использовании PID оставшаяся блокировка может потребовать ручной проверки. Повреждённый job-файл требует восстановления из backup; его содержимое не логируется.
- До 20 MiB оригинала, 10 страниц, 30000 символов суммарного текста для LLM; отдельные лимиты распаковки XLSX. Стили/даты/формулы XLSX не интерпретируются. Зашифрованные/повреждённые/слишком большие документы завершаются ошибкой; ручной ввод и скачивание оригинала доступны.
- JS heap/time limits не ограничивают всю native-память и не заменяют изоляцию/антивирус/сетевой контроль ИТ/ИБ. Контроль cloud flag и alias не является аудитом исходящего трафика корпоративного сервера.
- Два англоязычных синтетических PDF не характеризуют российские документы, плотные таблицы, рукопись, нагрузку или SLA. Русскоязычный эталонный корпус, пороги точности/времени и разрешение реальных документов ещё не согласованы. Gate D в полном объёме не принят.
