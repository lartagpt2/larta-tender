# TASK-008G — проверка и воспроизводимость

[Задание и протокол](../../tasks/TASK-008G.md), [handoff](../../handoffs/TASK-008G.md).
Все команды из корня репозитория после загрузки workspace окружения.

```powershell
node scripts/task008g/preserve-f.mjs
node --test scripts/task008g/metrics.test.mjs
node --test scripts/task008-gate-d/scoring.test.mjs
node scripts/task008g/verify.mjs
```

`preserve-f` проверяет 62 неизменных артефакта F, включая первичные метрики,
seal, эталоны, скрипты, PDF и полные jobs. Старый manifest F также содержал
production source v3; его полный verifier предназначен для checkout F, а не
для изменённого production v4. Старые F скрипты/manifest не переписываются.

`verify` пересчитывает новые primary из jobs, сверяет SHA источников и проверяет
каждую привязку валюты: документ, точную строку исходного PDF и якорь позиции.
БД и модель не вызываются. Локальные PDF/jobs необходимы: binary КП вне Git по
AGENTS.md, расположение в manifest/seal. Не заменять их перегенерированными PDF:
метаданные рендерера могут дать другой SHA при том же видимом содержимом.

Регрессия F: сохранённые первичные ответы той же модели пропущены через новый
детерминированный валидатор, без нового inference, исправления исходного артикула
или автоматического выбора TZ. Отчёт и локальные jobs записаны однократно (wx).
Новый набор G: отдельный первичный live проход после фиксации кода/документов/
эталонов/оценщика коммитом. Claim запрещает выборочные повторные прогоны.

Первичный live запуск уже выполнен, не повторять ради улучшения процента:

```powershell
$env:PGDATABASE = 'larta_test_task003'
node scripts/task008g/run.mjs --run-synthetic
```

Все успешные результаты needs_review. Числа из строки с несовпавшим артикулом
не засчитываются основным строгим оценщиком: кандидат из TZ — только предложение.
Основная пара = известная цена + известная валюта одной точно сопоставленной
позиции; ожидаемо неизвестная валюта оценивается отдельно как safety.

## Ручной сценарий в портале

1. В проверке КП выбрать документ, поступление, поставщика и лот с позициями TZ.
2. Запустить разрешённый синтетический документ явно: completed v3 jobs не
   перезаписываются автоматически, новая версия сохраняется отдельно.
3. Для строки посмотреть исходный артикул и Unicode-символы, затем кандидатов
   только текущего лота. Кнопка выбора меняет лишь выбор TZ в черновой форме.
4. Явно отметить подтверждение сопоставления, проверить количество/единицу,
   числовую цену и валюту. Валюта формы должна совпасть с валютой строки.
5. Нажать перенос в пустую строку: исходное описание/артикул не заменяются,
   заполненные цены не перезаписываются; сохраняется основание ручного действия.
6. Раскрыть «Валюта из заголовка — источник»: документ, страница/строка заголовка,
   фрагмент и расположение исходной позиции. Неоднозначные значения не заполнять
   предположением; неизвестные валюты не переносятся в бизнес-форму.
7. Сохранение AI-черновика не меняет сравнение. Подтверждение КП — отдельное
   действие закупщика; никаких автоматических подтверждений или отправки писем.

Реальные корпоративные документы не разрешены; merge только по решению владельца.
