# TASK-005 — Пакетная загрузка КП и группируемый реестр

**Зависимость:** принято TASK-004. **Прототип:** S03 и S04.

## Задача

Одна общая зона для загрузки множества КП и вложений от разных контрагентов. Не требовать выбора поставщика/email до загрузки. Повторная загрузка дополняет реестр без потери прежних документов.

## Состав

- Multipart batch API с лимитами, приёмом нескольких файлов, контрольной суммой SHA-256, MIME sniffing/проверкой расширений, per-file outcome и идемпотентностью.
- Хранение бинарников в корпоративном каталоге/объектном хранилище, согласованном с ИТ (настраиваемый адаптер; не хранить содержимое в PostgreSQL); сервер не должен выдавать произвольные системные пути.
- EML: заголовки From и вложения в пределах согласованного парсера; PDF/XLSX/ZIP без OCR помечать как ожидающие, ZIP безопасно разбирать лишь при утверждённом обработчике.
- Предварительная связь файлов с известным поставщиком по однозначному доказательству; при сомнении группа «Поставщик не определён» и ручное подтверждение.
- Аккордеон реестра по поставщикам, раскрывающий все файлы/этапы/приложения. Действие «Уточнить» обновляет связь, не оригинал.
- Подготовить расширяемый интерфейс `DocumentProcessingPort` для будущего локального OCR без фиктивных утверждений о распознавании.

## Приёмка

- [ ] Два захода загрузки суммарно 7 файлов дают 7 сохраняемых записей, если файлы действительно различны.
- [ ] Все приложенные файлы поставщика показываются внутри его группы.
- [ ] Email без доказательства остаётся пустым; неопределённые связи помечены.
- [ ] Архивы с опасными путями/лимитами безопасно отклоняются, события аудируются.
