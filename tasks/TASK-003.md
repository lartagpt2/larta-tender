# TASK-003 — Модель PostgreSQL, миграции и API-репозитории

**Зависимость:** принято TASK-002. **Основание:** `docs/DOMAIN_API.md`.

## Задача

Реализовать минимальные модели Tender, Lot, LotItem, Supplier, Document, Offer/OfferVersion, TenderStage, AccreditationReport, AuditEvent, FieldDecision, CostComponent; остальные сущности — по согласованному ERD. Не применяйте миграции к существующей БД без разрешения владельца.

## Состав

- ADR об ORM/миграциях после анализа того, что уже выбрано в репозитории (не навязывать вторую ORM).
- Миграции вверх, описание rollback/forward fix, индексы и FK; цена/количество — `NUMERIC`, не `FLOAT`.
- DTO и REST черновики `/api/tenders` и вложенных ресурсов; Swagger; проверка доступа, ошибок и аудит.
- Mock или test-db fixture с синтетическими объектами, отсутствие реальных клиентов.
- Тесты конкурентной записи/идемпотентности для входящих документов на уровне модели.

## Приёмка

- [ ] Предложение миграции просмотрено человеком до запуска.
- [ ] На согласованной пустой тестовой БД миграции воспроизводимы; схема сравнима с `docs/DOMAIN_API.md`.
- [ ] AuditEvent append-only, исходные документы и OfferVersion не обновляются незаметно.
- [ ] Приложен ERD, OpenAPI diff и handoff.
