# TASK-008G — артикулы, валюта и проверка пары цена + валюта

Разрешение владельца: после приёмки TASK-008F. База — feat/TASK-008F.

## Требования и границы

1. Выявлять похожие кириллические/латинские символы артикула; исходное написание
   rawValue/value не исправлять. Предлагать кандидатов только из ТЗ текущего лота.
   Выбор кандидата и перенос в форму — отдельные явные действия закупщика;
   окончательное подтверждение остаётся существующим отдельным действием.
2. В native PDF связывать валюту общего заголовка со строкой только при проверенных
   тексте, однозначном контексте и уникальном якоре строки. Хранить документ,
   страницу, строку и точный фрагмент источника. Не использовать валюту по умолчанию,
   не переносить валюту между документами/поставщиками. Конфликт/непроверяемость —
   null + предупреждение. Для сканов текст заголовка алгоритмически не доказан:
   сохраняется требование ручной проверки, без доверенного наследования.
3. Сохранить все первичные результаты, эталоны, PDF и jobs TASK-008F по SHA-256.
   После фиксации доработок использовать их для регрессии без изменения строгого
   первичного оценщика и без подмены артикула предлагаемым кандидатом.
4. До inference зафиксировать отдельный новый синтетический набор, эталоны,
   алгоритм оценки, версии production и SHA PDF. Единственный первичный проход,
   ошибки не исключать, не подстраивать алгоритмы до фиксации новых метрик.
5. Отдельно оценивать числовую цену + валюту одной строки: exact строгая связь по
   наименованию, цена известна в эталоне, валюта совпадает; все ошибки входят в
   знаменатель. Отдельно показывать кандидатное сопоставление и provenance,
   не считать предложение совпадения подтверждённой/исправленной номенклатурой.

Только синтетика и корпоративный Ollama qwen3-vl:8b-instruct с прежним digest.
Все AI-данные — needs_review/черновики, исходные цены и подтверждённые данные
не менять. Без миграций, установок, отправки писем и merge. ZIP — вопрос ИТ/ИБ.

## Проверки и результат

Unit/negative tests для омоглифов, неоднозначных кандидатов, пустых/чужих лотов,
сохранения исходников; для валюты — общий заголовок, разные валюты/таблицы,
отсутствующий заголовок, другая страница/документ, неверные evidence/метаданные.
Проверить UI явного выбора и отображение источника, safety очереди и сохранений.
Старые первичные метрики не повышать за счёт fuzzy matching или новых эталонов.

[Отчёт](../handoffs/TASK-008G.md) и PR к TASK-008F. Следующий этап — после приёмки.

## Независимый новый набор: протокол ДО inference

8 новых КП: 5 native, 3 скана; 9 страниц, 24 позиции. Новые поставщики,
ИНН и артикулы. Сценарии: EUR из общего заголовка, USD из заголовка таблицы,
RUB из заголовка на другой странице, два конфликтующих заголовка, сканы с
явной валютой, похожие артикулы, дробные м/кг, отсутствие валюты/цены.

Знаменатель основной пары: **18 строк с известными ценой и валютой**.
Отдельная safety-метрика: **5 строк с ценой, но ожидаемо неизвестной валютой**,
для них отсутствие валюты должно сохраниться; ещё **1 строка без цены**.
В основном знаменателе только точное сопоставление наименования/артикула,
типографическая нормализация неизменного scorer Gate D. Цена и валюта должны
совпасть вместе. Неизвестное значение не считается успешной известной парой.
Ошибки/сбои включаются, первичный проход один. Кандидаты омоглифов — отдельная
диагностика, не основание автоматически улучшать строгую оценку или подтверждать КП.

Исходные документы/эталоны, скрипты/оценщик и production hashes фиксируются manifest
и коммитом до нового inference. После его начала никаких изменений промпта,
алгоритмов и эталонов до фиксации primary/seal. Текущий этап реализует помощника,
а не выдаёт разрешение на реальные документы или автоматическое принятие цен.
